# 实验五前置知识

这次实验要解决两个问题：图像中哪些位置适合被稳定地重新找到？同一物体在照片里变大或变小时，怎样继续寻找它的特征？前一个问题引出角点，后一个问题引出尺度空间。检测出特征点之后，仍需要描述子和匹配才能建立两张图之间的对应关系；本实验主要学习检测。

## 1 图像就是数组

灰度图可以看成一个二维表，记作 I。每个位置记录亮度。常见 uint8 灰度图的取值范围是 0～255，0 表示黑，255 表示白。彩色图通常是 H×W×3 的数组；OpenCV 常用 BGR 通道顺序。

有两套顺序必须分清：

| 内容 | 顺序 | 示例 |
|---|---|---|
| NumPy 取像素 | 行、列，即 y、x | gray[y, x] |
| OpenCV 画点 | x、y | cv2.circle(img, (x, y), ...) |
| 数组形状 | 高、宽 | H, W = gray.shape |
| resize 目标尺寸 | 宽、高 | cv2.resize(img, (W, H)) |

例如 gray.shape 为 (480, 640)，右下角像素坐标是 (x, y)=(639, 479)，访问写成 gray[479, 639]。

**uint8 适合存图，不适合直接进行带负值的差分计算。** 两个像素 20 和 50 相减应为 -30。NumPy 的 uint8 数组相减可能回绕为 226；OpenCV 对 uint8 使用 cv2.subtract 会饱和截断成 0。先转 float32 再减才能保留符号：

```python
diff = a.astype(np.float32) - b.astype(np.float32)
```

读取失败得到的 None、形状为 (0, 0) 的空数组、所有像素都是 0 的黑图，是三种不同情况。黑图有正常尺寸，是合法的纯色图。

## 2 梯度告诉我们亮度变化有多快

想象一行像素：`20, 20, 20, 200, 200`。前三个位置亮度没有变化，20 跳到 200 的附近变化很强。梯度就是把这种变化量用数字表示。

横向梯度 Ix 表示沿 x 方向变化的快慢，纵向梯度 Iy 表示沿 y 方向变化的快慢。简单的中心差分可以写成：

```text
Ix(x,y) ≈ [I(x+1,y) - I(x-1,y)] / 2
Iy(x,y) ≈ [I(x,y+1) - I(x,y-1)] / 2
```

实际常用 Sobel 等算子，把邻域里的多个像素加权组合，估计梯度。所谓“卷积核”，在这里可以先理解成一个小模板：把它盖在图上，对应位置相乘后相加，滑动模板就得到整幅输出。边界处没有完整邻域，需要约定填充方法。

竖直黑白分界线，沿左右方向会跨过黑白边界，因此 Ix 大；沿上下方向仍停在同一侧，因此 Iy 小。**梯度方向大致垂直于边缘方向。**

仅看某一个像素的梯度大小还不足以判断角点：直线边缘也可能有很大的梯度。我们需要看一整个小邻域。

## 3 移动小窗口 理解什么是角点

在图上放一个小窗口，把窗口稍微移动，比较移动前后窗口里的亮度内容。

| 窗口位置 | 怎样移动时内容变化小 | 怎样移动时内容变化大 |
|---|---|---|
| 平坦区 | 各个方向都小 | 通常没有 |
| 直线边缘 | 沿边缘移动 | 横跨边缘移动 |
| 角点附近 | 没有明显容易滑动的方向 | 各个方向的小位移都会明显变化 |

例如一块纯白墙，很难根据小窗口确定自己沿墙移动了多少；一条笔直线，也很难确定沿线滑动了多少；到了线的拐角，左右上下移动都会改变窗口内容，定位更明确。

“各个方向”比“水平和竖直两个方向”更准确。一条斜边缘的 Ix 和 Iy 都可能较大，但沿斜边本身移动仍然变化小，它依然不是角点。

用公式记录窗口变化：

```text
E(u,v) = Σ w(x,y) [I(x+u,y+v) - I(x,y)]²
```

(u,v) 是小位移；平方避免正负变化抵消；Σ 表示在窗口内求和；w 是权重，可以让中心像素更重要。

对于足够小的位移，用一阶近似：`I(x+u,y+v)-I(x,y) ≈ Ix·u+Iy·v`。这相当于用当前位置的变化率估算附近的变化。代入并展开，就得到下一节的矩阵。[Harris 原理参考](https://docs.opencv.org/4.10.0/dc/d0d/tutorial_py_features_harris.html)

## 4 结构张量与特征值

把窗口内的梯度统计成三个数：

```text
A = Σ w·Ix²
B = Σ w·Ix·Iy
C = Σ w·Iy²

M = [ A  B ]
    [ B  C ]

E(u,v) ≈ A·u² + 2B·u·v + C·v²
       = [u v] M [u v]ᵀ
```

M 称为结构张量，也常称二阶矩矩阵；指导书把它称为自相关矩阵。每个像素位置都有自己的 M，并非整张图只计算一个矩阵。

不必先学习完整线性代数。这里先掌握：满足 `M q = λ q` 的方向 q 称为特征向量，对应倍数 λ 称为特征值。对于这个对称矩阵，可以选择两个相互垂直的单位特征方向。沿这些方向移动时，λ 表示窗口变化的强弱；在非负窗口权重下，两个 λ 都非负。

**λ1、λ2 对应的是两个主方向，不一定就是水平和竖直方向。**

| 两个特征值 | 图像类型 | 在 λ1 横轴、λ2 纵轴平面上的位置 |
|---|---|---|
| 都很小 | 平坦区 | 原点附近 |
| 一个大、一个小 | 边缘 | 靠近某一条坐标轴、离开原点 |
| 两个都大 | 角点 | 远离两条坐标轴的区域 |

“大”和“小”依赖图像数值范围、梯度算子及窗口，不能把下面的教学数值直接作为实际阈值。

三个可手算的例子：

```text
M平坦 = [[0,0], [0,0]]       → λ = 0, 0
M边缘 = [[100,0], [0,0]]     → λ = 100, 0
M角点 = [[100,0], [0,100]]   → λ = 100, 100
```

再看斜边：`M=[[50,50],[50,50]]`。两个对角元素都是 50，但特征值为 100 和 0！沿 (1,1) 方向变化强，沿 (1,-1) 方向变化弱。这说明不能只看 A 和 C 就断言是角点。

若需要手算一般情形，可以用：

```text
λ = [(A+C) ± sqrt((A-C)² + 4B²)] / 2
```

## 5 Harris 怎样给位置打分

Harris 不需要在每个位置显式求特征值，而是计算：

```text
det(M)   = A·C - B² = λ1·λ2
trace(M) = A + C    = λ1 + λ2
R = det(M) - k·trace(M)²
```

行列式 det 在一个特征值很小时会变小；trace 项对“只有一个方向特别强”的情况施加惩罚。

取 k=0.04：

| λ1 | λ2 | R | 解释 |
|---:|---:|---:|---|
| 0 | 0 | 0 | 理想平坦区 |
| 100 | 0 | -400 | 强边缘 |
| 100 | 100 | 8400 | 强角点 |
| 1 | 1 | 0.84 | 弱变化，不能仅凭 R>0 就保留 |

实际要保留“足够大的正响应”。同一个 M 下，k 增大一定使 R 减小。但如果每次都用 `0.01 * R.max()` 作为阈值，阈值本身也在变化，角点数量不保证严格随 k 单调变化。实验要同时记录参数、响应范围、筛选规则和点数。

`cv2.cornerHarris(gray, blockSize=2, ksize=3, k=0.04)` 返回响应图，并不直接返回角点列表。参数中 blockSize 控制统计邻域，ksize 控制 Sobel 梯度核，k 是评分系数。[接口说明](https://docs.opencv.org/4.x/dd/d1a/group__imgproc__feature.html)

从响应图到角点列表通常还有：阈值筛选 → 局部极大值筛选 → 限制点间距离。局部极大值筛选又叫非极大值抑制（NMS），直觉是“同一个峰附近只留下代表位置”。平顶峰可能仍有多个并列像素，需要额外去重。

指导书把所有超过阈值的像素涂红，适合观察响应区域，但红色像素数量不等于独立角点数量。不要拿未经去重的 Harris 像素数直接与 Shi-Tomasi 点数比较优劣。

## 6 Shi-Tomasi 与 FAST

Shi-Tomasi 使用 `score=min(λ1, λ2)`。它直接要求较弱的那个方向也有足够强的变化，因此适合选取易于跟踪的点。

```python
corners = cv2.goodFeaturesToTrack(
    gray, maxCorners=100, qualityLevel=0.01, minDistance=10
)
```

maxCorners 是最多保留多少个；qualityLevel 是相对最强质量分数的比例阈值；minDistance 是保留点之间的最小距离。minDistance 能减少聚集，但不保证各区域都有点。

默认使用 Shi-Tomasi；设置 `useHarrisDetector=True` 可用 Harris 评分。正常非空结果形状为 (N,1,2)，坐标是浮点数，没有角点时可能返回 None。因此不能未经判断就转换：

```python
if corners is None:
    points = np.empty((0, 2), dtype=np.int32)
else:
    points = np.rint(corners.reshape(-1, 2)).astype(np.int32)
```

绘图可取整；后续若要使用亚像素精度，可另存浮点坐标。[Shi-Tomasi 教程](https://docs.opencv.org/4.x/d4/d8c/tutorial_py_shi_tomasi.html)

FAST 是另一种检测方法，通过比较中心像素与周围圆周像素的亮暗关系寻找角点，通常用于快速检测，OpenCV 入口为 `cv2.FastFeatureDetector_create()`。指导书任务标题含“Fast”，但指定代码调用的是 Shi-Tomasi。FAST 的非极大值抑制也会使用评分，“FAST 完全没有评分”不准确。当前先完成明确指定的 Shi-Tomasi 对比即可。[FAST 教程](https://docs.opencv.org/4.x/df/d0c/tutorial_py_fast.html)

## 7 高斯模糊 尺度与金字塔

高斯模糊是按距离分配权重的邻域平均：近处影响大，远处影响小。σ（sigma）控制模糊范围，σ 越大，细小纹理越容易被平滑掉。模糊不是简单地把画面变差，它允许我们忽略小细节、观察较大的结构。

尺度可以先理解为“用多大的观察范围看结构”。固定大小的窗口观察近处物体与远处物体时，覆盖的物体比例不同，因此普通单尺度 Harris 不自动具有尺度不变性。

`pyrDown` 先平滑再大致将宽高各减半，提前平滑有助于减少降采样产生的混叠。512×512 图像的四层可以是 512、256、128、64。奇数尺寸按实际输出为准，默认通常向上取整。[金字塔教程](https://docs.opencv.org/4.13.0/dc/dff/tutorial_py_pyramids.html)

注意区分：

| 概念 | 改变什么 | 如何理解 |
|---|---|---|
| 同尺寸高斯尺度空间 | σ 改变，像素网格可不变 | 从细看逐步转为粗看 |
| 降采样金字塔 | 平滑后降低图像分辨率 | 用更少像素表示较粗结构 |
| SIFT 中的 octave | 一个倍率区间中有多个模糊层，之后降采样 | 同时组织模糊尺度与分辨率 |

金字塔第 i 层的点映回原图，基本坐标换算是乘以 2^i。例如第 2 层的 (20,30) 对应原图约 (80,120)。精细对齐还涉及重采样约定，这里先用于理解坐标尺度。

## 8 DoG 为什么要做差分

令 `L(x,y,σ)=Gσ * I`，即高斯平滑后的图。差分高斯为：

```text
D(x,y,σ) = L(x,y,s·σ) - L(x,y,σ), s>1
```

这里特意用 s 表示相邻尺度比，避免与 Harris 的参数 k 混淆。两个尺度观察结果的差异，能突出在这两个观察范围之间发生变化的结构。

标准 DoG 在同一像素网格上对不同模糊程度的图做差；不能直接把 512×512 和 256×256 数组相减。指导书先缩小、再放大对齐相减，是教学用跨层差分近似，包含重采样影响，不等同于完整 SIFT 尺度空间。

符合指导书操作意图、保留正负值的写法是：

```python
base = levels[0].astype(np.float32)
aligned = cv2.resize(
    levels[1].astype(np.float32),
    (base.shape[1], base.shape[0]),
    interpolation=cv2.INTER_LINEAR,
)
dog = base - aligned
mag = np.abs(dog)
dog_show = (255 * mag / max(float(mag.max()), 1e-6)).astype(np.uint8)
```

这里差分符号与上面的标准表达式相反，只会交换正负极值；分析时保持一致并说明即可。必须先转浮点再相减。若已经用 uint8 的 cv2.subtract 把 -30 截成 0，后续 abs(0) 无法恢复 30。

`dog` 用于计算，`dog_show` 仅用于显示。绝对值丢失符号，不能替代原始有符号数据；每层单独归一化也会掩盖层间真实幅值差异。

DoG 的亮区可能是边缘、斑点或其他变化结构，不能全部当作角点。完整 SIFT 的候选点要与同层 8 个邻居、上下尺度各 9 个邻居比较，共 26 个邻居，寻找空间与尺度上的极大值或极小值，再筛除不稳定响应。这样提升尺度变化下的可重复性，并不保证任意缩放、噪声和视角下都能重新找到同一个点。[SIFT 教程](https://docs.opencv.org/4.10.0/da/df5/tutorial_py_sift_intro.html)

## 9 编码前先约定输入输出

后续建议把函数约定明确为：输入二维、非空的灰度 NumPy 数组，支持 uint8 或有限值 float32；输出 (N,2) 整数坐标，列顺序为 x、y；没有角点返回 (0,2) 空数组。非法类型与空输入如何抛出异常，要在实现前统一。

这是建议的项目约定，不是说 OpenCV 本身只接受这一种封装方式。cornerHarris 支持 uint8 和 float32 灰度输入，无需把所有浮点图强制转回 uint8。用不同亮度数值范围时，响应大小也会变化。

pytest 的核心是用可重复的输入检查预期行为。`assert len(points)>0` 只能说明输出不空，不能证明点的位置正确。更有意义的后续检查包括：合成棋盘格交点附近能找到点、纯色图没有点、坐标合法、输入未被修改。

不要把“写了 5 个函数”当作测试充分。指导书的最低覆盖应包含合法输入、非法类型、空数组、纯色图、棋盘格、整数坐标及范围。代码示例只有 3 个测试函数，并没有替代这份完整要求。

## 10 指导书中需要特别辨清的地方

1. goodFeaturesToTrack 默认是 Shi-Tomasi，不是 FAST。
2. DoG 必须在相减前转浮点；先截断再取绝对值无法恢复信息。
3. 放大相邻金字塔层后相减是教学近似，不是完整 SIFT 检测。
4. 浮点灰度图不必一律转 uint8；先看接口支持的类型和数值范围。
5. “DoG 亮区就是关键点”和“任意缩放总能重检”都是过强的表述。
6. Git 默认合并可能 fast-forward，不一定出现单独的合并提交；推送 main 也不会自动推送 feature 分支。后续根据实际仓库状态操作，不能仅凭命令模板判断结果。
