# 自检与实验路线

## 第一轮 先回答这四题

1. 一条竖直黑白边界，向上移动窗口与向右移动窗口，哪个变化更明显？为什么？
2. 斜线边缘的 Ix 和 Iy 都不小，为什么仍然可能不是角点？
3. M=[[100,0],[0,1]] 与 M=[[40,0],[0,40]]，哪个更像角点？
4. λ1=100、λ2=1、k=0.04 时，Harris 响应是多少？

先独立想，再看答案：

1. 向右会跨过黑白边界，变化明显；向上沿边界移动，变化较小。
2. 沿着斜线仍然存在变化小的方向。特征值反映主方向上的变化，不能只检查水平、竖直分量。
3. 第二个。第一个有一个很弱的方向；第二个最弱方向也有足够变化。
4. R=100×1−0.04×101²=−308.04，更像边缘。

## 第二轮 进入编码前的检查

1. gray.shape=(300,500)，最大合法 (x,y) 是多少？
2. 为什么 Harris 阈值图中的 100 个红像素，不一定表示 100 个角点？
3. uint8 的 cv2.subtract 得到 0 后，再取绝对值能否恢复被截掉的负响应？
4. maxCorners=100 是否保证返回 100 个点？没有角点时怎样处理？
5. 512×512 连续三次 pyrDown 后尺寸是多少？总共有几层？
6. 金字塔相邻层能直接相减吗？对齐后相减是否等于完整 SIFT？
7. 纯黑图与空数组有什么区别？
8. 两幅 DoG 各自归一化后一样亮，是否代表原始响应一样强？

参考答案：

1. (499,299)，访问用 gray[299,499]。
2. 同一个角点周围可能有多个像素超过阈值，需要局部峰值筛选和去重。
3. 不能。应先转 float32 再相减。
4. 不保证；这是上限。None 应转成约定形状的空坐标数组。
5. 64×64；连同原图共有四层。
6. 不同尺寸不能直接逐像素相减；对齐差分仅是教学近似，还缺少尺度极值检测和筛选等步骤。
7. 纯黑图有有效尺寸，只是全零；空数组没有像素。
8. 不代表。各自归一化改变了显示比例，需要查看原始值或采用统一显示范围。

## 后续一起动手的路线

### 第一步 确认环境与准备图像

检查实际 Python 环境能否导入 cv2、numpy、pytest，记录版本；准备 data/chess.png，显示并确认读入成功。先检查 Git 仓库位置、当前分支和未提交文件，再按指导书创建开发分支。此阶段不应盲目初始化或覆盖已有仓库。

### 第二步 Harris

先看一幅响应图，再封装坐标提取。固定输入、窗口、阈值规则和去重方法，分别试 k=0.04、0.06、0.1，保存图并记录变化。能解释为什么响应区域和坐标列表是两种输出，再进入下一步。

### 第三步 Shi-Tomasi

在同一输入图的独立副本上绘制，避免把前一幅标注再次送入检测器。调整 qualityLevel 与 minDistance，观察点数和分布。比较两种方法时说明 Harris 是否去重、阈值是否一致，避免把“点多”等同于“效果好”。

### 第四步 金字塔与 DoG

记录 3～4 层图像实际尺寸；先完成指导书的跨层对齐差分，保留 float32 有符号响应，再生成显示图。若要进一步学习标准 DoG，再补同一网格上不同 σ 的模糊层和跨尺度极值检查。

观察目标是：哪些结构在哪些尺度更明显？是边缘、斑点还是角点附近？显示亮度与实际响应是否一致？不要提前写成“所有亮点都是关键点”。

### 第五步 测试

至少覆盖输入类型、空输入、纯色图、棋盘格有效输出、整数坐标和边界。测试棋盘格优先在内存中合成，使测试不依赖当前工作目录或下载图片。若封装了 DoG，还应检查输出形状、浮点类型、相同输入差为零和负值保留。

运行后记录真实结果；测试未执行前不写“全部通过”。

### 第六步 整理结果

完成 Harris 与 Shi-Tomasi 对比图、金字塔与 DoG 分析、测试输出截图、源码。加分项再做手写 Harris，并统一梯度、窗口、边界和缩放约定后比较响应；常量响应的相关系数可能无定义，需单独处理。

最后检查实际 Git 状态，完成本地提交和合并。是否存在远程仓库以及如何推送，留到该阶段依据实际情况处理。
