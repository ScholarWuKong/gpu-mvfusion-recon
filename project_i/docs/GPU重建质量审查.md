## 结论

目前应优先完善相机参数优化、BA 约束和观测生命周期，同时做 GPU ORB/匹配的单变量实验。GPU 加速实现也存在可优化的数据传输和分配路径，但不能把这些性能改进等同于几何精度改进。

当前没有真实三维模型或相机真值，因此不能证明某一项已经是视觉效果的唯一根因。下面分别标明源码确定的行为、导出数据的实测结果、以及仍需 A/B 验证的改进。

## 本次实测

同一批 `image1.jpg` 至 `image36.jpg`，按数字顺序，均使用 GPU 匹配和 GPU BA：

| 配置 | 注册图像 | 三维点 | 两视图点比例 | 平均重投影误差 | 单次运行时间 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 之前的 CPU ORB，10,000 特征 | 36/36 | 20,157 | 68.95% | 0.754 px | 120.51 s |
| 本次 GPU ORB，10,000 特征 | 36/36 | 18,353 | 72.47% | 0.696 px | 102.83 s |

时间是不同时间点的单次运行，不能视为严格性能基准。CPU/GPU 提取器的关键点、描述子及实现细节不同，点数和误差不能直接转化为几何质量排名。重投影误差只统计保留的有效观测，也不是三维真值误差。

GPU 10k 结果中：

- 13,301 个点只有两个有效已注册视图支持。
- 已关联点的观测中，8,919 条被禁用；被禁用不等于误删，需要分开统计真实外点和早期状态误判。
- 89,855 条原始匹配中，有 4,837 次同一图像对内目标特征被重复指派。
- 1,289 条几何内点匹配连接不同的三维点；其中 571 条满足双向交叉重投影误差均小于 2 px，涉及 364 个不同点对。
- 这些候选中，仅 4 个点对没有同图观测冲突。绝不能将 571 条候选直接认定为重复点，更不能简单删除 Track 的冲突检查。
- 有 17 个点的最终最大视差角小于 2°，最小约 0.991°。数量很少，不支持将整片点云的问题都归因于小视差。

CPU 10k 的对应交叉兼容匹配为 1,259 条、787 个不同点对，其中仅 7 对无同图冲突。此前关于“重复点”的观察应以这个限制解释。

## 优先改进项

### 1. 相机内参只有估计值，BA 不优化内参（质量优先）

位置：`src/app/application.cpp:160`、`include/geometry/types.h:7`、`src/ba/residual_internal.h`。

确定的代码行为：默认焦距固定为 `1.2 * max(width, height)`，主点固定在中心。公共 Camera 仅有 fx/fy/cx/cy；BA 只优化位姿与三维点，没有内参变量、共享相机参数块、畸变模型或标定文件读取。

影响：即便输入图像本身没有问题，不准确的投影模型仍可能被相机位姿和点深度吸收，出现形状偏差。小的重投影误差不能排除这种情况。没有内参真值，尚不能量化本数据集因此产生的形变。

建议：先提供已知内参的输入/固定模式；未知内参时，将同相机图像绑定到共享参数块，先优化带边界/先验的共享焦距。主点先固定；有证据需要时再添加低阶径向畸变，避免一次放开过多参数。GPU 残差与雅可比需要同步支持这些参数。

验收：已知内参保持不变；合成已知场景中，错误初始焦距能够收敛，经过 Sim(3) 对齐后的点/位姿真值误差降低，而不只检查代价下降。

参考：[COLMAP 内参共享与细化说明](https://colmap.github.io/faq.html#fix-intrinsics)。这里引用原理与实践，不建议替换当前工程或增加 COLMAP 依赖。

### 2. 两台初始相机完全固定，限制了后续 BA 的纠错能力（质量优先）

位置：`src/sfm/initializer.cpp:31`、`src/ba/optimizer.cpp:103`、`tests/integration_checks.cpp`。

确定的代码行为：两台 seed 相机均列入固定集合；整个增量流程不再优化它们。

影响：单目重建的整体相似变换有 7 个自由度；完全固定两台相机通常约束过多。第二台相机的初始旋转和基线方向误差不能被后续大量观测修正。现有测试让两台 seed 的位姿完全正确，主要扰动第三台相机，覆盖不到这个问题。

建议：固定第一台相机，并增加一个明确的尺度约束；释放第二台相机剩余位姿自由度。不要直接释放全部相机，否则会引入规范自由度和奇异系统。GPU/CPU 数值一致性应继续保留。

验收：给第二台 seed 添加已知旋转及基线方向扰动，检查其误差能够降低；首相机与尺度约束保持稳定，优化系统无退化。

### 3. 观测被过早永久禁用，三角化缺少稳健重估（质量优先）

位置：`src/sfm/incremental_mapper.cpp:146`、`:154`、`:156`，`src/sfm/observation_manager.cpp:12`、`:49`，`src/geometry/triangulation.cpp`。

确定的代码行为：在 BA 前先按当前三维点的位置禁用超过阈值的观测；禁用后没有重新激活流程。已有点跳过重三角化。未建点 Track 则将全部已注册观测一次性送入线性 DLT，并要求每个视图都通过误差阈值。

影响：一个错误观测可能阻止整条原本可用 Track 建点；一个早期不准确的点也可能导致后来的正确观测被禁用，失去帮助修正该点的机会。BA 后只检查重投影和观测数量，没有重新验证视差/不确定性。

建议：使用候选视图对进行稳健三角化，选择内点观测集合，再做非线性点精修；对新视图关联区分暂定、确认、外点状态。位姿更新后允许重新验证暂定/被拒观测，并对已有点重三角化。最终输出分离两视图暂定点与三视图以上确认点；不要在初始化阶段无条件删除全部两视图点。

验收：一条含多个正确观测和一个错误观测的 Track 仍能建点；初始点有偏差时，新加入的正确观测能够参与修正；BA 后的低视差点得到降级或过滤。

### 4. GPU 匹配只做单向 Ratio Test，没有一对一与互检（前端质量）

位置：`src/matching/gpu_feature_matcher.cpp:115`、`:133`。

确定的代码行为：只计算 imageId 较小一侧到另一侧的 KNN，满足 ratio 即保留。多个 query 可以指向同一 train；规范化顺序不会替代匹配互检。

建议：保留 OpenCV CUDA BF/Hamming 后端，增加可配置的反向 KNN/互为最近邻检查，并在同一图像对内选择一对一对应。严格互检可能降低召回率，需要在相同特征和输入下单独比较，不能预设必然改善。原始匹配仍应保留，筛选与几何内点继续用索引关联。

验收：目标特征重复指派得到控制；注册覆盖不明显下降，长 Track 占比、几何内点质量和已知场景三维误差改善。

### 5. GPU ORB 的描述子预处理与 CPU 不一致，值得做低成本实验（GPU 专有）

位置：`src/feature/gpu_feature_extractor.cpp:25`，本地 `third_party/opencv/include/opencv2/cudafeatures2d.hpp:472`。

确定的代码行为：创建 cuda::ORB 时没有传最后一个 `blurForDescriptor` 参数，因此沿用默认 false。OpenCV CPU ORB 4.12 在计算描述子前有高斯平滑步骤。

建议：显式暴露该配置，在相同 10k 特征预算下仅切换 blur 做对照；它可能改善描述子稳定性，但本轮没有试验 true，不能宣称已经提升效果。同时统计关键点的图像网格覆盖和 octave 分布，必要时增加空间配额，筛选时必须同步维护描述子行索引。

验收：分别比较候选匹配/内点数量、Track 长度、覆盖率、位姿与形状误差；不能只比较特征数量。

参考：[OpenCV CUDA ORB 参数](https://docs.opencv.org/4.13.0/da/d44/classcv_1_1cuda_1_1ORB.html)、[OpenCV 4.12 CPU ORB 源码](https://raw.githubusercontent.com/opencv/opencv/4.12.0/modules/features2d/src/orb.cpp)。CUDA 默认值也已用本地 4.12 头文件核对。

### 6. Track 融合及回环连接需要几何处理，不能直接放开合并（质量与完整性）

位置：`src/sfm/track_builder.cpp:92`。

确定的代码行为：两个 Track 已各自有点时直接拒绝合并；同一图像有冲突观测时同样拒绝。没有三维点融合和冲突观测选择流程，也没有在新全局位姿下重新尝试已有连接。

建议：保留冲突保护；增加基于多视图重投影、位置不确定性和观测一致性的融合/重估。无同图冲突且几何一致的点对可先作为最小实现。同图冲突应选择可验证的代表观测，不能把两者都塞进 Track。已有匹配图支持跨段边，但缺少点融合与后续重优化使部分连接未能变成有效约束。

验收：正确融合保持每图最多一个观测，错误连接仍被拒绝，所有 Track/Point ID 双向映射一致。点数下降可能代表消除重复，不能仅以“点更多”衡量。

### 7. 初始化过于依赖输入顺序（中期改进）

位置：`src/sfm/incremental_mapper.cpp:127`、`src/sfm/initializer.cpp:17`。

确定的代码行为：在线加入第二张图片后就尝试初始化，此时候选图通常只有第一对；按内点数排序并不能在整批图片中选择较优的初始基线。

建议：为批量应用提供小规模 bootstrap 候选集，综合有效三角化数量、视差、内点分布、退化检验选择 seed，再优先注册有最多可靠 2D-3D 约束的图像。不要默认处理每个候选对都使用原始全图匹配。

本数据集并未显示大面积接近零视差；此项是顺序敏感性和泛化能力风险，不应当作已证明的主要根因。

### 8. GPU BA 每次评价都分配与传输，主要求解仍在 CPU（执行效率）

位置：`src/ba/gpu_bundle_adjuster.cu:35`、`:41`，`src/ba/optimizer.cpp:31`、`:172`、`:236`、`:241`。

确定的代码行为：每次 evaluateGpu 新建两块设备缓冲，上传按观测重复展开的相机/点参数，下载全部残差和雅可比。每步试探还复制整个 Reconstruction。Hessian 装配、Schur 消元和稠密求解均在 CPU，GPU 只负责残差和雅可比。

建议的实施顺序：

1. 先按阶段记录耗时与传输字节，使用 CUDA events/Nsight 确定占比；本轮未采集 profiler，因此不提供速度提升比例。
2. 将 GPU 缓冲改为优化器持有、按容量增长，复用设备内存；按 camera/point/observation 分块传参，减少重复展开。
3. 残差与 Jacobian 留在 GPU，逐步将块 Hessian/梯度装配及点块消元迁入 CUDA，优先回传较小的 Schur 系统。
4. 增量阶段使用共视邻域的局部 BA，定期或闭环后做充分全局 BA；最终输出前做质量过滤与再次优化。
5. 确认问题规模和精度后，再评估使用已有 CUDA Toolkit 的 cuBLAS/cuSOLVER 或迭代 Schur 求解。避免未经验证地全部降为 float。

这部分有明确的结构性优化空间，但减少分配和拷贝本身不会自动修正点云形状。

## 测试需要补的内容

现有集成测试使用确定性合成特征；GPU ORB 主要覆盖空输入/空特征情形。它证明接口链路和部分数学实现可运行，但不足以验证一般图像上的重建质量。

应补充：seed 位姿扰动、错误初始焦距、混合正确/错误观测、已有点加入新视图、Track 点融合冲突、GPU 描述子稳定性，以及受控噪声下经过 Sim(3) 对齐的位姿/三维点精度。真实 36 图可作为回归集，但没有真值时需同时检查覆盖、三视图以上点比例、冲突数、闭环一致性和误差分布。

本轮未改代码，因此没有重复执行未受影响的编译与 CTest。没有新增独立 Demo/main、依赖或 CUDA 架构改动。

## 建议实施批次

- 第一批：GPU ORB blur 单变量实验、双向/一对一匹配开关、稳健三角化与观测重验证；记录阶段指标。
- 第二批：正确的 BA 规范约束、共享内参模式、可靠的点融合与最终全局优化；补充有真值的几何回归。
- 第三批：持久 GPU 缓冲、设备端块装配/Schur、局部/全局 BA 调度；使用 profiler 评估收益。

以上仍属于 SfM 稀疏重建。若期待连续表面和密集点云，后续还需 MVS；它解决的目标与本轮稀疏几何优化不同。
