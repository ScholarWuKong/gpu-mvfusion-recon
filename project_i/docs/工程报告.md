## 3. 架构与 CMake

依赖方向为公共类型 → 几何 → 场景数据 → 算法接口/实现 → SfM 编排 → 应用创建组件。几何不依赖 scene/SfM；scene 不包含提取器、匹配器、BA 或 IO。公共算法接口不暴露 OpenCV 的 Mat/GpuMat。

CMake 显式组织 `sfm_util`、`sfm_geometry`、`sfm_scene`，以及 feature/matching/BA 的 api、具体实现和 factory targets；上层为 `sfm_mapper`、`sfm_io`、`sfm_app` 和唯一可执行目标 `project_i`。`sfm_mapper` 只依赖抽象接口，CPU/GPU 实现互不依赖；BA 共享后端无关求解代码。

保留 CMake 最低版本 3.24、C++17/CUDA17、项目内 OpenCV 4.12 预编译布局、CUDA Toolkit 查找、原架构设置和 OpenCV DLL 复制。只调用 OpenCV CUDA API 的提取器与匹配器均为 `.cpp`；只有自定义 BA kernel 的文件按 `.cu` 编译。

## 4. 数据链与关键约束

`FeatureSet.imageId_` 与描述子行索引 → 规范化的 `ImagePair` / 原始 `FeatureMatch` → `inlierMatchIndices_` → 无同图冲突的跨图像 Track → Observation → 注册相机位姿与三维点 → BA。

- 图像对反转时，原始匹配的特征索引同步交换。原始匹配与几何内点分别保留。
- 空匹配也保存 attempted 状态；未知 ID、重复 ID、错误维度及非法索引会被拒绝。
- GPU 匹配缓存比较完整描述子内容，避免同 ID 的新数据误用旧内容；提供 `clearCache()`，资源由 GpuMat 管理。
- Track 扩展拒绝同图冲突，避免重复观测；合并与压缩同步维护 Track/Point 双向索引。两个已关联三维点的 Track 不直接合并。
- PnP 精修后再次检查正深度与重投影误差；三角化检查正深度、最小视差和误差。点失去两个有效已注册观测的支持时，移除该点并修复紧凑 ID。
- `addImage` 仅请求新增图像与候选图像的边，旧匹配和特征保留。匹配器返回不完整结果时，回滚新增特征，允许重试。

## 5. 实际执行的验证

在项目根目录执行：

```powershell
cmake -S . -B build -A x64 -DBUILD_TESTING=ON
cmake --build build --config RelWithDebInfo --parallel 4
ctest --test-dir build -C RelWithDebInfo --output-on-failure -V
.\build\RelWithDebInfo\project_i.exe --self-test
```

配置成功：CMake 4.2.1、VS2022/MSVC、OpenCV 4.12.0、CUDA 12.8.61。首次受限环境构建停在 MSBuild 构建系统检查，终止后使用已安装编译工具链重试成功。最终完整编译退出 0。没有更改 CUDA 架构；保留已有 compute_52/sm_52 设置。

最终 CTest：1/1 集成测试通过，退出 0。测试覆盖真实 CPU/GPU ORB 的空图像/零关键点、真实 CUDA 多图匹配与缓存、几何内点索引、三角化精度及零基线拒绝、Track 冲突与合并、点清理后的索引、解析雅可比对照中心差分、BA 数值一致性，以及增量候选与失败后重试。

## 6. 限制与未完成项

- 真实输入只验证了两视图初始化与点优化，真实第三图及后续注册尚未验证。当前默认使用估计焦距，没有校准内参或测量真实几何误差，不能宣称达到重建精度指标。
- CPU BA 为原生 LM/Schur，未接入 Ceres；GPU BA 加速残差和雅可比，矩阵装配与 Schur 求解仍在 CPU，尚非全 GPU BA。
- 两台初始相机完全固定，内参不优化；相机系统为稠密矩阵，最多支持 256 台可变相机。
- 输入需已去畸变；CLI 只支持公共焦距，尚未实现标定文件读取、畸变模型、自动候选检索、显存淘汰和已有三维点的跨 Track 融合。
- MVS 保留扩展目录，没有填充无功能实现。CUDA stream/event/pool 等未使用占位文件也未填充。
- OpenCV 自带 CMake 配置仍有 CMP0146 开发警告；CUDA 对现有旧架构发出未来弃用警告。当前均不影响实际构建与运行。
